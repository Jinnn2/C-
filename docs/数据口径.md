# 时间、计量与数据契约

## 时间

- 时区统一为 Asia/Shanghai。SQLite与CSV中的时间为当地ISO时间字符串，不含UTC偏移，不作UTC混算。
- 日d的slot从1到144；第k段为[d 00:00+(k-1)×10分钟, d 00:00+k×10分钟)。interval_end是右边界标签，最后一段归属日d，不归属次日。
- 原始0:10到0:00+1的144个值，按右端标签代表此前10分钟段处理。这是离散化假设：题面没有明确这些功率是瞬时值还是区间均值，不能声称已证实为真实区间平均功率。
- 基准日没有真实日期，baseline表只保存slot及起止分钟；不擅自赋予某个季节或日期。
- 实际数据最早可用时间保守设为interval_end；0:00时只可使用此前已完成的区间。电价的真实发布时间未给出，price_available_at是供在线仿真使用的保守假设，不是源数据事实。
- 预报的issue_time为发布日期与发布时刻；target_time=issue_time+lead_hours，lead_hours=1..24。空白日期只在同一个预报工作表内向下继承。
- 12月31日预报合法覆盖2026年1月1日；保留它们，标记缺乏实际观测对照，不误判为缺失数据，也不伪造次年实际值。

## 计量

- 原始负载与光伏功率kW保留；建模电量kWh=功率kW/6。浮点全精度计算，仅展示时舍入。
- 电价元/kWh；费用=电价×电量，不再次乘1/6。
- c是电网侧充电输入、d是电网侧放电输出；电池内能增加0.9c、减少d/0.9。
- 每段电网侧充、放电各自上限833.333333... kWh；可用SOC窗口9600 kWh，不能将铭牌12000当成允许调度窗口。

## 预报时间细化

forecast_hourly保留原始小时预报，作为权威源表。forecast_10min是单独的派生表：

1. 第1小时内各10分钟右端点采用该次发布的第1小时预报值（first_hour_hold）。
2. 第1至24小时之间，相邻整点预报线性插值；所有整点严格还原原预报。
3. 以派生功率/6作为该10分钟段的预测电量，这是与主数据相同的右端矩形积分近似，不是源文件提供的10分钟预报，也不保证精确日能量。
4. 每条派生记录保留发布时间、预测提前分钟、左右源单元格与方法；不使用任何实际光伏值插值。第一小时采用保持值，是缺少发布时刻预报锚点时的透明基线，可在后续预测验证中替换。
5. 不擅自按固定钟点清零或裁剪光伏；原始非负值经上述方法保持非负。

## 表结构与用途

- baseline：附件1的144段固定价格、负载、光伏预测及换算电量。
- actuals：附件2负载/光伏、附件4实际价格，365×144条；含固定价格，便于第二三问结算。未来行仅用于事后评分，表存在不代表决策时可见。
- forecast_hourly：1460次发布×24小时，共35040条。
- forecast_10min：1460次发布×144段，共210240条。
- template_time_mapping：模板原时间标签、单元格位置、按顺序规范化的标签及变更标记。该映射是建议修正，不证明原标签本来就具有规范化含义。
- metadata：单位、时区、假设、储能参数。
- source_files：源文件SHA256、大小与相对路径；每条原始记录另保留源工作表/单元格，便于追溯。
- daily_summary.csv：逐日能量、价格、负净负载段数，仅用于描述统计，不能当成日前特征。

主数据库为data/processed/microgrid.sqlite；同名CSV用于查看和交换。不得以去重、平滑、填零等操作覆盖原始附件。结构错误、非法数值、日期/时点缺失导致脚本失败；模板问题和合法预测越界记录为警告。所有插值和输出均可通过脚本重建。

## 模板修正原则

内部统一生成0:00–0:10至23:50–24:00的144段。模板普遍从0:10–0:20开始，末尾跨日标签也有歧义；保留原模板，导出时用规范标签创建结果副本，并在报告中注明修正。充放电和紧急购电表仅是示例行，需要根据全部334个输出日期及真实事件动态扩展，不能只填现有行。当前阶段仅生成映射，不填写策略结果。
